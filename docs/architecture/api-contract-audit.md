# PHP route registry / OpenAPI contract audit

**Basis:** Static comparison of `api-backend-php/api/routes.php` and `api-backend-php/swagger/openapi.json`, including expansion of the route file's `posts`/`polls`/`events` loops. Also inspected the relevant PHP handlers, client call sites and test source for request/response/security details. No tests, builds, runtime calls or contract edits were made.

## Result

- **110 registered method/path operations:** 95 literal `addRoute()` calls plus 15 routes generated by the nested resource loops.
- **70 distinct registered path patterns** after expanding those loops; replacing every placeholder (including named/typed differences) with one generic marker reduces that to 69 path shapes.
- **89 registered operations have a matching OpenAPI method/path** after comparing the API v1 server prefix and normalizing parameter constraints; **21 registered operations have no OpenAPI operation**.
- **0 OpenAPI operations are extra** relative to the registered PHP route set.
- The 21 omissions are the `/groups/member-candidates` route and group posts, polls and events content/participation routes. The generated loop contributes 15 of those operations (5 each for posts, polls and events); explicit poll/event actions contribute the rest.

“Match” here means method and normalized path presence only. It does not establish runtime parity, request/response schema correctness, or client interoperability. PHP constraints such as `{id:[0-9]+}` are not represented by the same syntax in OpenAPI `{id}`.

## OpenAPI request, response and security evidence

- `swagger/openapi.json` is OpenAPI 3.0.3. Its server URL is `../api/v1`; the path keys omit that prefix. It defines `BearerAuth` and the reusable `ApiSuccess` / `ApiError` schemas. The document has no global security requirement.
- **85 of the 89 documented operations explicitly declare `BearerAuth`.** Four operations have no operation-level bearer requirement in the document: `POST /auth/login`, `POST /auth/admin/login`, `GET /invitations/{code}`, and `POST /invitations/{code}/accept`. Do not infer access policy for omitted route operations from this OpenAPI document.
- **44 operations declare a JSON `requestBody`; 45 do not.** For example, login request bodies declare `username` and `password`; refresh and logout declare `refresh_token`. The OpenAPI login response points to `ApiSuccess`; errors use the documented `ApiError` model. Operation-specific response codes and field schemas remain as written in the file; the generic component model does not prove a handler's emitted payload.
- For the 21 absent operations, OpenAPI supplies no operation-level request, response or security details. Those details must not be reconstructed from names alone. PHP handler behavior is source evidence and is described under the feature specs where reviewed.
- OpenAPI schemas and route presence were inspected, not executed or exhaustively validated field-by-field against every handler. OpenAPI “Present” is not a claim that the Angular/Ionic client request matches.

## Material mismatches evidenced in source

- The omitted group resource routes are implemented by `api-backend-php/api/groups/resources.php`; resource loop routes map posts/polls/events to shared content handling. The checked OpenAPI has no request/response/security contracts for those routes.
- The admin program/trainer/batch/session services use update verbs that differ from registered `PUT` routes; other academic paths include the unregistered batch-member add route, cancel path/body differences, session-lock path differences, and attendance payload key mismatch. See `requirements/features/programs-participation/technical-spec.md`.
- Payment filters/form fields, notification path/body fields and activity-log date fields differ between client and server sources. See the relevant feature technical specs and `docs/development/baseline-gap-report.md`.
- No report route is registered; report page paths are not defined in OpenAPI. This is a missing endpoint surface, not a basis for inferring report behavior.

## Test-source note

`api-backend-php/tests/phase7-parity.php` checks literal route registrations, handler files, and migration inventory entries. Its regex scans `addRoute()` statements and does not expand the resource-generation loop. Its assertions were read only; this audit did not execute it.
