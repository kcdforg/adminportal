## UI-ADM-019-01 — Member Form: Screen structure

**Requirement:** The member form screen presents the task with a clear identifying heading.

**Acceptance criteria:**
- The screen displays its main content with a clear heading.

**Previous screen-level ID:** `UI-ADM-019`

## UI-ADM-019-02 — Member Form: Input controls

**Requirement:** The member form screen provides clearly labeled controls appropriate to the task.

**Acceptance criteria:**
- The screen provides controls for the information needed to complete the task: first_name (input); last_name (input); email (input); mobile (input); gender (select); date_of_birth (input); status (select).

**Previous screen-level ID:** `UI-ADM-019`

## UI-ADM-019-03 — Member Form: User actions

**Requirement:** The user can complete the actions available on this screen.

**Acceptance criteria:**
- The screen clearly offers the available actions: Cancel.

**Previous screen-level ID:** `UI-ADM-019`

## UI-ADM-019-04 — Member Form: Conditional UI states

**Requirement:** The member form screen communicates loading, empty, error, and unavailable states when they apply.

**Acceptance criteria:**
- The screen explains when data cannot be loaded or an action fails; indicates when an action is unavailable.

**Previous screen-level ID:** `UI-ADM-019`
