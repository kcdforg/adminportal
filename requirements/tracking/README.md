# Requirement Change Tracking

Use `pending/changes.md` to summarize proposed requirement additions, edits, and removals that have not yet been accepted by the product owner.

Each change entry should include:

- The requirement ID or affected document.
- Whether it is new, modified, or removed.
- A short reason for the change.
- Any open product or policy decision.

Requirement review and implementation are separate activities. Do not mark a requirement approved, implemented, or verified merely because its document was edited. Record implementation and test results separately when work begins.

When a change set is accepted or implementation begins, move its record to the appropriate tracking state only if the team is using that process. Keep the pending file current and avoid treating a draft change log as a sign-off.
