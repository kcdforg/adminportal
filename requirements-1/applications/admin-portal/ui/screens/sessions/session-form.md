# Session Form

This document describes the expected user-facing behavior of this screen or component.

## Status

Working draft. Confirm the behavior and any role or policy rules with stakeholders before approval.

## UI-ADM-031-01 — Session Form: Screen structure

**Requirement:** The session form screen presents the task with a clear identifying heading.

**Acceptance criteria:**
- The screen displays its main content with a clear heading.

**Previous screen-level ID:** `UI-ADM-031`

## UI-ADM-031-02 — Session Form: Input controls

**Requirement:** The session form screen provides clearly labeled controls appropriate to the task.

**Acceptance criteria:**
- The screen provides controls for the information needed to complete the task: session_date (input); session_type (select); start_time (input); end_time (input); title (input); topics_covered (textarea); homework (textarea); notes (textarea); status (select).

**Previous screen-level ID:** `UI-ADM-031`

## UI-ADM-031-03 — Session Form: User actions

**Requirement:** The user can complete the actions available on this screen.

**Acceptance criteria:**
- The screen clearly offers the available actions: Cancel.

**Previous screen-level ID:** `UI-ADM-031`

## UI-ADM-031-04 — Session Form: Conditional UI states

**Requirement:** The session form screen communicates loading, empty, error, and unavailable states when they apply.

**Acceptance criteria:**
- The screen explains when data cannot be loaded or an action fails; indicates when an action is unavailable.

**Previous screen-level ID:** `UI-ADM-031`
